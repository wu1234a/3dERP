# 第三阶段计划：销售订单到生产任务的闭环

| 字段 | 值 |

| 对应仓库里程碑 | M3.1 ~ M3.5（见 [milestones.md](milestones.md)） |

## 1. 背景与目标

阶段 1 已交付客户 / 供应商 / 物料 / 仓库主数据，阶段 2 已交付库存流水、余额与预警。
本阶段打通最小业务闭环：

```text
销售订单(草稿) → 确认 → 创建生产任务 → 领料耗用(库存出库)
      → 完工登记(成品入库) → 销售发货(销售出库) → 订单完成
```

目标：

1. 建立销售订单域：订单 + 订单行 + 状态机，落地为主数据之后第一组业务单据。
2. 建立生产任务域：任务、排产时间字段、材料耗用与完工登记。
3. 复用阶段 2 的库存流水机制完成领料出库、成品入库、销售出库三类联动记账，
   余额与流水保持一致，禁止负库存。
4. 前端补齐"销售"与"生产"两个模块页面，替换现有 `ModuleView` 占位页。
5. 用 WebApplicationFactory 集成测试验证整条闭环。

## 2. 范围

### 包含

- 销售：销售订单（含行）的创建、确认、取消、发货；行级发货数量跟踪与部分发货。
- 生产：生产任务的创建（可关联订单行）、开始打印、后处理、完工、取消；材料耗用登记。
- 库存联动：领料出库（Out）、成品入库（In）、销售出库（Out），全部走阶段 2 的
  流水 + 余额机制，流水 `DocumentNo` 按 `{任务/订单单据号}-{类型}-{序号}` 生成保证唯一。
- 前端：`SalesOrdersView.vue`、`ProductionTasksView.vue` 及对应 API 客户端。
- 测试：各任务单元测试；阶段末的闭环集成测试。

### 不包含（留待后续阶段）

- 报价单、应收应付、发票等财务单据（财务模块）。
- 采购申请 / 采购订单 / 收货（采购模块）。
- 排产算法、设备台账、后处理工单拆分（本期仅保留排产时间字段与任务状态）。
- 多级 BOM 与工艺参数库。
- 权限、审计、单据自动编号规则（阶段 4 的系统模块；本期单据号仍由调用方传入）。

## 3. 关键设计决策

| 决策 | 说明 |
| --- | --- |
| 状态机集中校验 | 状态流转规则放在 Application 服务层（`SalesOrderService` / `ProductionTaskService`），endpoint 只做参数接收与结果映射，非法流转抛 `ConflictException` 返回 409 |
| 单据不做物理删除 | 订单 / 任务 / 发货单只有"取消"，无 DELETE 端点；草稿行的调整仅限草稿态 |
| 发货数量跟踪 | 订单行的 `ShippedQuantity` 在首个迁移 `AddSalesOrders` 中即建立（避免二次迁移）；发货以发货单（`SalesShipment` + 行）落库，库存只认流水 |
| 单据号 | 沿用阶段 2 约定：调用方传入 `DocumentNo`，同表唯一、2-64 位、去除首尾空白；联动流水号由服务端按 `{父单据号}-C/F/S-{序号:00}` 生成，同类型唯一防重 |
| 金额与数量 | 全部 `decimal`，数量 `decimal(19,4)`，单价 `decimal(19,4)`，禁止 `double` |
| 时间 | 一律 UTC 存储，属性名以 `Utc` 结尾 |
| 主键 | `Guid.CreateVersion7()` |
| 并发 | 单据头与行均带 `rowversion`（`byte[] RowVersion`）乐观并发令牌 |
| 迁移 | 三个迁移对应三个后端里程碑：`AddSalesOrders`（M3.1）、`AddProductionTasks`（M3.2）、`AddSalesShipments`（M3.3），保证每个里程碑可独立评审与回滚 |

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 状态流转分支多，容易遗漏非法路径 | 每个服务的流转规则用表格写进任务文档；单元测试逐条覆盖非法流转 409 |
| 发货与库存扣减的原子性 | 发货单、行、`ShippedQuantity` 与库存流水在同一数据库事务内提交（参照 `IInventoryRepository.RecordMovementAsync` 的事务实现），任一行库存不足整单回滚 |
| 联动流水单据号冲突 | 序号由服务端在同一事务内取"已有最大序号 + 1"，流水表 `(MovementType, DocumentNo)` 唯一索引兜底，冲突返回 409 |
| 迁移与既有库冲突 | 迁移命名固定（`AddSalesOrders` / `AddProductionTasks` / `AddSalesShipments`），评审时检查 `ErpDbContextModelSnapshot` 无意外改动 |
| 前端与 API 字段漂移 | 前端任务依赖对应后端任务完成后再开发，字段以任务文档中的 DTO 为准 |
